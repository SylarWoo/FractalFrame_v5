# 20_图表系统链路收口与后续优化计划

记录时间：2026-06-12

## 1. 前因后果

当前项目已经从早期单体图表宿主逐步迁移到 KLineChart 渲染系统 V2。

早期系统主要围绕 `ChartCoreHost.tsx` 展开，里面同时承载：

- KLineChart 实例生命周期
- StoreV6 数据加载
- 实时 tick 合并
- 指标加载与卸载
- 画图工具接入
- 视口、Y 轴、分页、实时页缓存

随着 StoreV6、V2 分页、V2 渲染、V2 实时窗口、指标总控台、画图模块不断加入，继续把新能力塞回 `ChartCoreHost.tsx` 会导致链路混乱。

本轮优化的核心目标是：

1. 明确 V2 主链路。
2. 把旧链路隔离到 `legacy/`。
3. 让当前能运行的底座继续稳定。
4. 后续再逐步删除旧代码，而不是一次性硬删。

## 2. 已完成的关键链路


V2 图表系统已经负责：

- K 线渲染

- 历史页和实时页组合
- V2 视口恢复
- V2 Y 轴恢复
- V2 图表标题覆盖层

### 2.2 StoreV6 与分页链路

当前数据底座已经以 StoreV6 为核心：

```text

-> pagePartition
```

已经加入的重点能力：

### 2.3 指标链路

### 2.4 画图模块链路

画图模块已经从旧渲染系统接入到 V2 图表：


### 2.5 旧图表链路隔离

已经完成两步隔离：

第一步：把原来从 `ChartCoreHost.tsx` 导出的共享类型抽走。

现在共享类型放在：

```text
frontend/src/workbench/chart/chartRuntimeTypes.ts
```

包括：

- `ChartLoadState`
- `ChartPageTarget`
- `ChartPageNavigation`
- `ChartIndicatorCommand`

第二步：把旧图表宿主 hooks 和旧 page/window/viewport 模块移入：

```text
frontend/src/workbench/chart/legacy/
```

当前 legacy 目录包含：

```text
legacy/
  README.md
  useChartInstance.ts
  useChartRealtimeTicks.ts
  useChartRealtimeTicks.test.ts
  useChartDataLoad.ts
  useChartStepLoad.ts
  chartViewportPersistence.ts
  chartAdapter/
  pageLoader/
  pageWindow/
```

这样以后看到 `legacy/` 就知道它属于旧 `ChartCoreHost`，新 V2 功能不应该继续往里面加。

## 3. 当前代码链路现状

### 3.1 V2 主链路相对清晰

V2 主链路已经集中在：

```text
chart/
  ChartWorkspaceV2.tsx
  chartRuntimeTypes.ts
  klineChartRendererV2/
  klineChartRenderFrameV2/
  realtimePageWindowV2/
  indicatorRequestV2/
  pagePartition/
  pageSliceV2/
  pageData/
```

这部分是后续继续开发的主区域。

### 3.2 旧链路已经被标记但还不能马上删除

`ChartCoreHost.tsx` 目前仍然存在，但它已经不再被外部当成类型仓库使用。

旧 hooks 已经进入：

```text
chart/legacy/
```

下一步要继续判断：

- 哪些 legacy 模块还有运行价值
- 哪些只是兼容旧入口
- 哪些可以在确认 V2 完全接管后删除

### 3.3 仍然不能随便移动的共享模块

以下模块虽然名字看起来旧，但当前 V2 仍在使用，不能直接搬进 legacy：

```text
chart/realtimePageBuffer.ts
chart/chartCoreDataUtils.ts
chart/pageData/
```

原因：

- `realtimePageBuffer.ts` 仍被 V2 实时页、实时价格标记、workbench 事件监听使用。
- `chartCoreDataUtils.ts` 仍被 V2 pageSlice 读取使用。
- `pageData/` 仍承担页面指标计算、page calculation context、指标结果缓存。

这些模块下一步要做的是重命名、拆边界、标注用途，而不是直接删除。

### 3.4 右侧抽屉样式存在共享命名问题

最近发现 Drawings 抽屉按钮 CSS 会偶尔丢失，原因是：

- Drawings 复用了 Indicators 的 class。
- Drawings 是 lazy chunk。
- 如果 Indicators 没先加载，Drawings 里的按钮会退回浏览器默认样式。

已临时修复：

```text
DrawingsDrawer.tsx
-> import './IndicatorSettingsShellLayout.css'
```

长期应该抽成真正共享的右侧抽屉控件样式，而不是继续复用 `ff-indicators-*` 命名。

## 4. 后续 6 个优化步骤

### 第一步：清理 `realtimePageBuffer` 的身份

当前 `realtimePageBuffer.ts` 名字像旧实时页缓存，但 V2 仍然在使用它。

要先判断它的真实身份：

- 如果它只是旧实时页缓存，后续迁入 `legacy/`。
- 如果它是 V2 仍需要的共享实时事件桥，就改名。

候选命名：

```text
workbenchRealtimeBuffer.ts
realtimeSharedBuffer.ts
chartRealtimeBridge.ts
```

同时要把旧 key 标注清楚：

```text
fractalframe:chartRealtimePageBuffer:v1
fractalframe:chartRealtimePageSnapshot:v1
fractalframe:chartRealtimePageIndexCache:v1
```

这些 key 要么标记为 legacy fallback，要么迁移到新的 V2 profile key。

### 第二步：抽清 `pageData/` 边界

`pageData/` 当前仍是 V2 指标计算需要的共享模块。

它应该只负责：

- page data package
- page data cache
- page data key
- page indicator calculator
- page calculation context

不应该继续承担旧 page window 的概念。

如果发现旧 page window 相关转换逻辑，应继续放进：

```text
chart/legacy/pageWindow/
```

### 第三步：给 chart 目录补主 README

建议新增：

```text
frontend/src/workbench/chart/README.md
```

内容写清楚：

- V2 主入口：`ChartWorkspaceV2`
- V2 渲染：`klineChartRendererV2`
- V2 frame：`klineChartRenderFrameV2`
- V2 实时：`realtimePageWindowV2`
- V2 指标：`indicatorRequestV2`
- 旧链路：`legacy/`
- 共享模块：`pageData/`, `pagePartition/`, `chartRuntimeTypes.ts`

这样后续开发时不会继续误碰旧模块。

### 第四步：右侧抽屉状态继续统一

之前已经确定状态文件应该分三类：

1. KLineChart 渲染系统 V2 通用配置。
2. 每周期 UI / 指标 / 按钮设置。
3. 每周期物理数据 JSON。

当前已有：

```text
frontend/src/workbench/persistence/periodUiStateStorage.ts
```

下一步要把这些状态继续归并：

- 指标加载状态
- 指标设置状态
- Drawings 持久化状态
- Settings 里按周期生效的按钮状态
- 快捷周期菜单状态

目标是减少散落 localStorage key，让 M5 / M30 / H2 等周期互不污染。

### 第五步：继续瘦身 `chartDrawingTools.ts`

画图模块已经有五个 installer，但 `chartDrawingTools.ts` 仍然偏大。

下一步可以拆：

```text
chartDrawingPersistenceBridge.ts
chartDrawingObjectTreeBridge.ts
chartDrawingInteractionInstaller.ts
chartDrawingSelectionRegistry.ts
```

目标：

- `chartDrawingTools.ts` 只负责装配。
- 五个工具 installer 只负责各自工具。
- object tree、persistence、interaction 不互相混。

### 第六步：最后再删旧代码

不要现在直接删 `ChartCoreHost.tsx`。

正确顺序：

1. 确认外部不再 import `ChartCoreHost.tsx`。
2. 确认运行入口只走 `ChartWorkspaceV2`。
3. 确认旧 hooks 只在 `legacy/` 内被引用。
4. 确认 legacy 目录没有被 V2 主链使用。
5. 最后把 `ChartCoreHost.tsx` 改名为 `LegacyChartCoreHost.tsx` 或删除。

删除旧代码之前必须保证：

```text
npm.cmd run test:logic -- --run src
npm.cmd run build
```

全部通过。

## 5. 执行原则

后续优化不要一次性大删。

推荐策略：

1. 先移动和改名。
2. 再修 import。
3. 再跑测试和 build。
4. 再观察运行。
5. 最后删除旧 fallback。

每次只处理一类链路：

- 类型依赖
- legacy hooks
- legacy page/window
- realtime buffer
- pageData
- drawing module
- right drawer shared UI

这样可以避免把已经跑通的 M5 / M30 / H2、MR-H2、VWAP、实时窗口、指标和画图模块再次弄乱。
