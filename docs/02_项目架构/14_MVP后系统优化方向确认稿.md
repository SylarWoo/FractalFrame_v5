# MVP 后系统优化方向确认稿

## 1. 文档目的

当前项目已经进入最小可用 MVP 阶段。后续优化不再以“哪里坏了补哪里”为主，而是围绕已经形成的 V2 主链路做系统收口。

本文用于确认后续优化的主方向：

1. 图表渲染必须以 `KLineChartRenderFrameV2` 为唯一主输入。
2. 指标必须通过 V2 request、window 计算、frame 合并、生命周期挂载进入图表。
3. 实时尾部必须保留实时跳动能力，但不能在拖动画面时抢主线程。
4. 分页、刷新恢复、跨周期画线必须有明确锚点和持久化规则。
5. 后续每次优化都要补对应守门测试，避免已经修好的链路回退。

## 2. 当前主链路确认

### 2.1 数据到渲染主链路

当前图表主链路应固定为：

```text
MT5 / 本地缓存
  -> StoreV6 分页与实时窗口
  -> 指标 V2 请求与预热计算
  -> 历史窗口 / 实时窗口合并
  -> KLineChartRenderFrameV2
  -> KLineChart V2 apply controller
  -> KLineChart 生命周期挂载
```

这条链路是后续优化的基准。任何指标、画线、分页、实时刷新问题，都优先检查是否完整进入这条链路。

### 2.2 指标主链路

指标不能再只靠右侧抽屉 UI 状态或局部 overlay 补挂载。正规链路必须包含：

1. 指标定义。
2. 工作区 registry 注册。
3. `AppShell` request 入口。
4. 历史页计算。
5. 实时页计算。
6. frame 合并。
7. KLineChart 生命周期挂载。
8. 标题、数值、样式、可见范围、Y 轴和 pane 高度恢复。
9. 对应测试。

主图指标走主图 overlay 生命周期，副图指标走 KLineChart 子窗格生命周期。`VOL` 已经回到正规 KLineChart indicator 链路，不能再回退到外部 canvas 补绘。

### 2.3 实时尾部主链路

实时页的要求不是“少更新”，而是“正确更新”：

1. 实时页必须持续接收后台 tick 和本地缓存补救数据。
2. 最新一根 K 线可以走 tail update，避免整页重绘。
3. 用户拖动画面时，tail update 可以延后，但不能触发 full frame 抢渲染。
4. 停盘、日结、周结、月结必须触发对应窗口重建和分页更新。
5. 实时尾部指标必须和历史页指标使用同一套计算口径。

因此，实时跳动不能被关掉；要优化的是 apply 调度、窗口命中、overlay 生命周期和拖动期间的更新策略。

## 3. 已经确认的系统边界

### 3.1 V2 与旧系统边界

V2 图表系统负责：

1. frame 接收。
2. full frame / pane-only / tail update 判断。
3. 分页跳转锚点。
4. 实时尾部更新。
5. 指标生命周期挂载。
6. pane 高度和 Y 轴恢复。
7. 图表 overlay 刷新。

旧系统可以作为参考，但不应继续承担新的主链路职责。旧逻辑如果要复用，应先独立成模块，再接入 V2 的边界点。

### 3.2 鼠标事件边界

鼠标事件已经开始拆成 V2 独立模块。后续规则：

1. 图表基础鼠标行为归 V2 鼠标事件模块管理。
2. 画图工具鼠标行为单独作为 drawing mouse module 接入。
3. 箭头、十字星、拖动手型、画线工具光标，不应散落在多个组件里。
4. 后续新增画图工具时，先接 drawing mouse module，再接工具业务。

### 3.3 跨周期画线边界

跨周期画线是画图系统的独立能力，不属于指标系统。

当前确认规则：

1. 只覆盖 `M5`、`M30`、`H2` 三个主周期。
2. 水平线按价格共享。
3. 趋势线按锚点 K 线和价格共享。
4. 每条线使用同一个 ID 在不同周期同步。
5. 勾选目标周期是共享 allow-list，不是单端口临时状态。
6. 修改后应通过事件通知同步，不使用高频轮询。
7. 勾选状态和目标周期必须持久化。

## 4. 已补的守门测试方向

当前已经补充或确认了以下测试方向：

1. 分页锚点：向历史页翻、向实时页翻、跳页翻时，窗口左侧或右侧锚点必须符合分页方向。
2. 实时尾部：同一 render window 内尾部更新使用 tail update；拖动画面时不抢渲染。
3. 跨周期画线：跨周期目标只允许 `M5`、`M30`、`H2`，勾选目标作为所有端口共享 allow-list。
4. MMAD：主图指标标题和数值必须显示在主图标题栏。
5. V2 apply controller：full frame overlay 不允许重复刷新。

这些测试不是为了追求覆盖率，而是为了锁住已经反复修过的高风险链路。

## 5. 后续优化优先级

### 5.1 第一优先级：交互性能

重点观察：

1. 鼠标移动是否触发无意义计算。
2. 拖动画面时是否触发 full frame apply。
3. overlay 是否重复 update。
4. 右侧抽屉状态变化是否影响图表主渲染。
5. 跨周期画线同步是否产生多端口重复刷新。

验收标准：

1. 拖动画面时没有明显间歇性卡顿。
2. 实时页仍然跳动。
3. 历史页不会因为后台 tick 疯狂计算。
4. 开关右侧抽屉不影响主图分页标签和画线交互。

### 5.2 第二优先级：刷新恢复一致性

重点周期：

1. `M5`：日结后重新分页。
2. `M30`：周结后重新分页。
3. `H2`：月结或周起点对齐后的窗口重新计算。

验收标准：

1. 刷新后指标 pane 高度不被压回默认值。
2. 副图 Y 轴手动缩放恢复。
3. 当前页、实时页、历史页位置恢复正确。
4. MMAD、VWAP、MR、VOL 等主图指标都能恢复标题、样式和数据。

### 5.3 第三优先级：指标模块化

后续新增指标必须优先做成稳定模块：

1. 计算模块独立。
2. 输入参数独立。
3. 输出数据结构稳定。
4. 主图或副图生命周期明确。
5. 样式控件和标题显示接入统一框架。
6. 历史页和实时页使用同一算法。

MMAD 的后续判断重点不是“看起来像 VWAP”，而是确认它表达的是不是用户需要的摩根区间成交量压力。如果算法定义继续变化，应先在计算模块里收口，再处理展示。

### 5.4 第四优先级：文档和测试同步

后续每完成一条系统性优化，都要同步三件事：

1. 更新架构文档。
2. 增加守门测试。
3. 记录验证命令。

文档只写已经确认的链路，不写临时猜想。临时方案应该进入任务笔记，不进入架构主文档。

## 6. 后续禁止事项

1. 禁止为了修某个指标显示问题，绕过 V2 request 直接操作 KLineChart。
2. 禁止为了修实时尾部，关闭实时页后台跳动。
3. 禁止用高频轮询解决跨周期同步。
4. 禁止新增外部 canvas 作为指标主渲染路径。
5. 禁止只验证 `M5`，不验证 `M30` 和 `H2`。
6. 禁止把画图工具鼠标事件继续散落在多个 UI 组件里。
7. 禁止只改 UI 显示，不补对应状态持久化。

## 7. 当前建议的下一步

下一步可以按下面顺序继续：

1. 做一次交互性能审计：鼠标移动、拖动、实时 tick、右侧抽屉开关。
2. 把 V2 鼠标事件模块继续收口，尤其是 drawing mouse module。
3. 给跨周期画线同步增加事件级测试，锁住“改一端，其它端立即同步”。
4. 给 M5 / M30 / H2 的日结、周结、月结刷新恢复补更细的测试。
5. 再回头整理指标文档，把 MMAD、MR、VWAP、VOL 的主图生命周期写清楚。

这套顺序的核心是：先稳交互主链路，再扩展功能。否则继续加指标或画图能力时，卡顿和恢复问题会反复出现。
