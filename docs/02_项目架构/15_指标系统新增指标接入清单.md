# 指标系统新增指标接入清单

本文档用于约束后续新增指标的标准接入流程，避免重新回到分散补丁式接入。

## 1. 定义层

- 在 `frontend/src/workbench/rightDrawer/indicatorDefinitions.ts` 增加指标行定义。
- 在 `frontend/src/workbench/rightDrawer/indicatorPersistence.ts` 增加 settings 类型、默认值、读写归一化。
- 如果指标需要右侧抽屉快捷菜单，确认 `indicatorRows` 和顶部快捷菜单共用同一份定义。

## 2. 设置面板

- 新指标面板优先使用 `frontend/src/workbench/rightDrawer/indicators/panels/IndicatorSettingControls.tsx`。
- 常用控件：
  - `NumberBox`：数字输入。
  - `CheckControl`：勾选控制。
  - `IndicatorSelectRow`：标准下拉菜单行。
  - `IndicatorLineStyleRow`：勾选 + 线型色板。
  - `IndicatorColorStyleRow`：勾选 + 颜色色板。
  - `IndicatorLineValueStyleRow`：勾选 + 线型色板 + 数值输入。
- 独立指标优先拆成单独 `*SettingsPanels.tsx`，不要继续无边界扩张 `indicatorPanelComponents.tsx`。

## 3. 计算与请求层

- 新 V2 指标优先放入 `frontend/src/workbench/chart/indicatorRequestV2/`。
- 指标请求构建统一经过 `chartIndicatorRequestBuilderV2.ts`。
- 主图指标和副图指标要明确分流：
  - 主图：叠加到价格 pane，注意标题和值展示。
  - 副图：走独立 pane，注意高度恢复、右侧刻度、分页快照。

## 4. 渲染层

- KLineChart 生命周期入口优先走 `klineChartIndicatorLifecycleV2.ts`。
- 主图自绘覆盖层放在 `klineChartRendererV2/` 内独立模块。
- 副图指标优先复用现有 sub pane 模式，不要绕过 pane 高度和快照链路。

## 5. 持久化与分页

- 加载状态、设置项、顶部快捷菜单状态必须分别验证。
- M5、M30、H2 三个主周期都要验证刷新后恢复。
- 实时页和历史分页要分别验证，实时页不能因为历史页优化失去尾部更新。

## 6. 验证

最低验证命令：

```bash
npm.cmd run build
npm.cmd run test:logic -- --run src\workbench\rightDrawer\indicatorIntegrationChecklist.test.ts src\workbench\rightDrawer\indicatorDefinitions.test.ts src\workbench\rightDrawer\indicatorPersistence.test.ts src\workbench\chart\indicatorRequestV2\chartIndicatorRequestBuilderV2.test.ts
```

新增指标如果包含独立算法，必须补充对应算法测试。

`indicatorIntegrationChecklist.test.ts` 是新增指标的接入模板测试，主要覆盖：

- 指标列表和 controller restore 顺序一致。
- 每个指标都有 loaded 状态和默认 settings。
- 每个指标能生成 load command。
- 每个可加载指标都能进入 `chartIndicatorRequestBuilderV2`。
