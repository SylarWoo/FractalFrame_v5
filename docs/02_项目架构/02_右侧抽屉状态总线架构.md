# 右侧抽屉状态总线架构

## 1. 目标

右侧抽屉是工作台的“账户状态面板”。当前 5185 端口运行起来以后，绘图、对象树、指标、策略、MT5 数据中心、设置都在右侧抽屉里操作，但这些状态现在分散存在 localStorage、内存事件、StoreV6 状态缓存、实时页缓存里。

新的状态总线文件用于把 `5185` 这个运行端口视为一个独立身份，统一记录这个端口下右侧抽屉相关状态。

核心原则：

- `port:5185` 先作为当前工作台身份 ID。
- 状态总线记录“当前状态”和“最近事件”，不是 K 线仓库本体。
- StoreV6 的 parquet、索引、分页文件仍然归 StoreV6；状态总线只记录它们的扫描结果、当前选择、分页视图状态、最近一次更新信息。
- 浏览器 localStorage 可以继续作为快速 UI 缓存；状态总线文件作为后续统一持久化和恢复的主设计。
- 策略模块先保留接口，不强行做完整策略状态。

建议落盘路径：

```text
runtime_data/runtime_state/port_5185/right_drawer_state.json
```

如果后面支持多个窗口或多个端口，则扩展为：

```text
runtime_data/runtime_state/port_{port}/right_drawer_state.json
```

## 2. 当前代码现状

右侧抽屉入口类型已经固定在：

```ts
type RightDrawerId = 'drawings' | 'objectTree' | 'indicators' | 'strategy' | 'mt5' | 'settings'
```

对应截图顺序：

1. 绘图：`drawings`
2. 对象树：`objectTree`
3. 指标：`indicators`
4. 策略：`strategy`
5. 数据中心：`mt5`
6. 设置：`settings`

当前主入口状态：

| 状态 | 当前 key |
| --- | --- |
| 当前打开的右侧抽屉 | `fractalframe:rightWidgetActiveDrawer:v1` |
| 右侧抽屉宽度 | `fractalframe:rightWidgetDrawerWidthPx:v1` |
| 底部抽屉开关 | `fractalframe:bottomDrawerOpen:v1` |
| 底部抽屉高度 | `fractalframe:bottomDrawerHeightPx:v1` |
| 数据中心共享选择 | `fractalframe:mt5ImportCenterSharedSelection:v1` |
| 设置页整体对象 | `fractalframe:settingsSymbolPanel:v1` |

这些 key 已经能恢复一部分 UI，但没有“5185 端口身份文件”，也没有统一描述“当前这个端口现在处于什么状态”。

## 3. 状态总线文件结构

建议文件根结构：

```ts
type RightDrawerStateBusFile = {
  schemaVersion: 'right_drawer_state_bus_v1'
  runtimeScopeId: 'port:5185'
  port: 5185
  origin: 'http://127.0.0.1:5185'
  createdAt: string
  updatedAt: string
  active: {
    drawer: RightDrawerId | null
    symbol: string | null
    period: string | null
    runtimeKey: string | null
  }
  layout: RightDrawerLayoutState
  modules: {
    drawings: DrawingsModuleState
    objectTree: ObjectTreeModuleState
    indicators: IndicatorsModuleState
    strategy: StrategyModuleState
    mt5DataCenter: Mt5DataCenterModuleState
    settings: SettingsModuleState
  }
  events: {
    lastEventAt: string | null
    tail: RightDrawerStateEvent[]
  }
}
```

`runtimeKey` 建议统一为：

```text
{symbol}:{period}
```

例如：

```text
XAUUSD:M5
```

后面如果要区分账户、模板、窗口，可以扩展为：

```text
{accountId}:{port}:{symbol}:{period}:{layoutId}
```

## 4. 顶层状态

### 4.1 active

记录当前工作台正在看的核心身份：

```json
{
  "drawer": "mt5",
  "symbol": "XAUUSD",
  "period": "M5",
  "runtimeKey": "XAUUSD:M5"
```

触发来源：

当前已有 key：

- `rightWidgetActiveDrawer`
- `rightWidgetDrawerWidthPx`
- `bottomDrawerOpen`

## 11. 事件模型

状态总线不是只保存静态 JSON，还应该记录最后一批关键事件，方便排查“为什么停了”“谁触发过更新”。

建议事件结构：

```ts
type RightDrawerStateEvent = {
  id: string
  at: string
  type:
    | 'right_drawer_opened'
    | 'right_drawer_closed'
    | 'right_drawer_resized'
    | 'symbol_changed'
    | 'period_changed'
    | 'drawing_created'
    | 'drawing_updated'
    | 'drawing_deleted'
    | 'object_visibility_changed'
    | 'indicator_loaded'
    | 'indicator_unloaded'
    | 'indicator_settings_changed'
    | 'strategy_loaded'
    | 'strategy_unloaded'
    | 'mt5_scan_completed'
    | 'store_status_checked'
    | 'manual_prepare_started'
    | 'manual_prepare_completed'
    | 'manual_prepare_failed'
    | 'daily_0600_prepare_started'
    | 'daily_0600_prepare_completed'
    | 'daily_0600_prepare_failed'
    | 'realtime_page_buffer_changed'
    | 'realtime_page_rollover_requested'
    | 'realtime_page_rollover_completed'
    | 'settings_changed'
  source: 'ui' | 'frontend_runtime' | 'backend' | 'scheduler'
  runtimeKey?: string
  symbol?: string
  period?: string
  message?: string
  payload?: unknown
}
```

事件尾巴只保留最近 50 到 200 条，不做无限日志。用户界面上如果只想显示一条“最新更新信息”，就从 `modules.mt5DataCenter.storeV6.lastPrepare` 读，不需要维护日志列表。

## 12. 触发关系

### 12.1 右侧抽屉切换

触发：

- 写 `active.drawer`
- 写 `layout.rightDrawer.activeDrawer`
- 追加 `right_drawer_opened` 或 `right_drawer_closed`

### 12.2 品种切换

触发：

- 写 `active.symbol`
- 写 `active.runtimeKey`
- 写 `modules.mt5DataCenter.selection.symbol`
- 追加 `symbol_changed`
- 后续由图表和数据中心决定是否扫描仓库、加载缓存、订阅 tick

### 12.3 周期切换

触发：

- 写 `active.period`
- 写 `active.runtimeKey`
- 写 `modules.mt5DataCenter.selection.period`
- 检查当前 symbol/period 的实时页缓存
- 检查 StoreV6 分页索引
- 追加 `period_changed`

周期切换本身不应该直接乱落盘。它应该触发“状态检查”和“必要时补偿”，补偿仍走 StoreV6 的 M1 拉取聚合链路。

### 12.4 实时页缓存满 2500

触发：

- 追加 `realtime_page_rollover_requested`
- 调用 StoreV6 主链路：拉 M1、聚合、更新历史分页
- 成功后写 `modules.mt5DataCenter.storeV6.lastPrepare`
- 重置当前 runtimeKey 的实时页缓存窗口
- 追加 `realtime_page_rollover_completed`

### 12.5 每日 6 点

触发：

- 追加 `daily_0600_prepare_started`
- 调用 StoreV6 主链路：拉 M1、聚合、更新历史分页
- 成功后覆盖 `modules.mt5DataCenter.storeV6.lastPrepare`
- 追加 `daily_0600_prepare_completed`

用户界面只显示 `lastPrepare` 这一条。例如：

```json
{
  "source": "daily_0600",
  "completedAt": "2026-06-03T06:00:12+08:00",
  "status": "success",
  "message": "6:00 自动拉取、聚合、更新完成"
}
```

如果后面手动更新发生在更晚时间，则覆盖这条：

```json
{
  "source": "manual",
  "completedAt": "2026-06-03T14:18:33+08:00",
  "status": "success",
  "message": "14:18 手动拉取、聚合、更新完成"
}
```

规则是：最新日期时间覆盖旧更新信息，不是固定“手动覆盖 6 点”。

## 13. 和 StoreV6 的边界

状态总线归工作台运行态，StoreV6 归数据仓库。

状态总线可以记录：

- 当前选中 symbol/period。
- 当前仓库扫描时间。
- 当前仓库最新 K 线 ID。
- 当前 MT5 最新 K 线 ID。
- 两边差多少根。
- 最近一次拉取聚合更新状态。
- 实时页缓存有多少根。
- 触发过哪些补偿事件。

状态总线不记录：

- M1 原始 K 线全集。
- 聚合后的 M5/M15/M30/H1 全量 K 线。
- parquet 正文。
- 指标计算结果正文。
- 回测明细结果正文。

这样可以保证状态总线小、可读、可修复；仓库文件仍由 StoreV6 专门管理。

## 14. 迁移建议

第一步：只增加状态总线读写模块，不移除现有 localStorage。

第二步：所有右侧抽屉写 localStorage 的地方，同时写状态总线。

第三步：启动时优先读状态总线，再兼容旧 localStorage。

第四步：把散落 key 分模块收口：

- `rightDrawerStateBus.ts`：统一读写状态总线。
- `drawingsStateAdapter.ts`：绘图旧 key -> 总线。
- `objectTreeStateAdapter.ts`：对象树旧 key -> 总线。
- `indicatorsStateAdapter.ts`：指标旧 key -> 总线。
- `strategyStateAdapter.ts`：策略预留。
- `mt5DataCenterStateAdapter.ts`：数据中心、StoreV6 状态、实时页状态。
- `settingsStateAdapter.ts`：设置页 `settingsSymbolPanel` -> 总线 sections。

第五步：当总线稳定后，再考虑清理 v5 命名残留。当前 `fractalframe:v5:indicators:*` 是指标持久化命名残留，但它只影响指标模块，不会干扰 StoreV6 仓库主链路。
