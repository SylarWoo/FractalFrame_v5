# 指标系统与页面规划器架构

本文记录 FractalFrame 当前指标系统的整体设计。核心目标是把“单个指标包”和“页面级指标规划器”分开：指标包只负责自己的计算和渲染，页面规划器统一决定当前页 K 线窗口、身份对齐、缓存写入和 KLineChart 生命周期读取。

## 1. 核心结论

指标系统分三层：

```text
单个指标包
-> 页面指标规划器 / 规则器
-> KLineChart 生命周期渲染
```

其中：

- StoreV6 只保存干净 K 线、分页索引、OHLCV 和数据中心主链状态。
- 指标结果不写入 StoreV6 仓库。
- 指标包各自独立，不互相依赖运行状态。
- 页面规划器统一控制当前页 K 线窗口和指标计算范围。
- KLineChart 的 `calc` 只读当前页指标快照，不偷偷跨页取数，也不兜底全量重算。

## 2. 单个指标包

每个指标包应该保持独立边界。典型文件包括：

```text
tradingViewRsiIndicator.ts
tradingViewMacdIndicator.ts
tradingViewVdoIndicator.ts
tradingViewVmiIndicator.ts
tradingViewVwapIndicator.ts
mainVolumeIndicator.ts
```

单个指标包负责：

- 指标参数归一化。
- 指标纯计算函数。
- KLineChart 注册。
- tooltip 和状态行显示。
- draw 生命周期绘图。
- 读取当前页缓存的 KLineChart calc 入口。

标准形态：

```ts
calculateTradingViewXxxRows(realRows, settings)
calculateXxxRowsForKLineChart(dataList, calcParams)
ensureTradingViewXxxIndicator()
```

其中：

- `calculateTradingViewXxxRows` 是纯计算函数。
- `calculateXxxRowsForKLineChart` 是 KLineChart `calc` 入口，只读页面规划器写好的当前页快照。
- `ensureTradingViewXxxIndicator` 只负责注册、绘图和 tooltip。

## 3. 页面指标规划器

当前页面指标规划器由这些模块组成：

```text
frontend/src/workbench/chart/pageIndicatorRuntime.ts
frontend/src/workbench/chart/indicatorPageSnapshotStore.ts
frontend/src/workbench/chart/chartIndicatorCommandHandlers.ts
frontend/src/workbench/chart/ChartCoreHost.tsx
```

职责：

- 识别当前页面模式：`realtime | history | jump`。
- 生成当前页 `pageKey`。
- 读取当前页 K 线窗口。
- 为每根 K 线建立 `barKey`。
- 检查同页 K 线身份唯一性。
- 调用各指标纯计算函数。
- 把结果写入页级 snapshot。
- 维护 `settingsHash`。
- 让 KLineChart `calc` 只读 snapshot。

规划器不是指标算法。它只负责“这一页应该算什么、写到哪里、怎么对齐”。

## 4. K线身份

指标不能只靠数组下标对齐。数组下标只是当前页面中的位置，不是稳定身份。

统一身份规则：

```text
barKey = symbol + period + openTime
```

当前实现中由 `barIdentity.ts` 和 `pageIndicatorRuntime.ts` 统一处理。

强制规则：

- 当前页每根 K 线必须有唯一 `barKey`。
- 指标结果写入 snapshot 时按 `barKey` 落位。
- KLineChart 读取指标结果时，按当前 `dataList` 的 `barKey` 找回结果。
- 找不到结果就返回空对象，不跨页找，不拿旧页补。
- 指标可以保留 `sourceIndex` 作为辅助信息，但不能把它当作唯一身份。

## 5. 实时页窗口

实时页不是固定死的 2000 根，也不是普通历史第一页。

实时页窗口规则：

```text
起点：由分页器确定，第一页起点固定
初始窗口：2000 根
活动终点：实时 K 线持续追加
最大窗口：2500 根
到达阈值：触发 StoreV6 主链更新，然后重置分页窗口
```

所以实时页的本质是：

```text
固定起点 + 活动终点 + barKey 身份对齐
```

实时页增长时：

- K 线窗口从 2000 增长到最多 2500。
- 新进 K 线必须带当前周期身份，例如 `M5` 页就是 `M5` K 线。
- `volume` 必须来自当前周期 MT5 rate volume，不用 M1 volume 替代。
- 指标按当前实时页窗口重新写当前页 snapshot。
- KLineChart 只读当前页 snapshot 渲染。

## 6. 实时VOL规则

实时页 VOL 属于当前周期 K 线的一部分，不属于指标补偿逻辑。

当前约定：

```text
5185 当前图表周期是 M5
实时页缓存就是 M5 K 线缓存
活动 K 线的 volume 应来自 MT5 的 M5 rate volume
```

规则：

- 不做“临时回补 volume”。
- 不把 M1 volume 当作 M5 当前 K volume。
- tick 到来时，可以事件触发查询 MT5 当前周期 rates。
- 用当前周期 K 线 openTime 匹配 MT5 rate row。
- 匹配到就更新当前活动 K 的 `volume`。
- 匹配不到就保留已有 volume，不编造数据。

这保证 VWAP、Volume、VWMA 等依赖 volume 的指标使用的是当前周期一致的数据。

## 7. 页级快照

页级指标快照结构由 `indicatorPageSnapshotStore.ts` 管理。

核心结构：

```ts
type IndicatorPageSnapshot = {
  pageKey: string
  symbol: string
  period: string
  settingsHash: string
  settingsHashes?: Record<string, string>
  rows: IndicatorPageSnapshotRow[]
  byBarKey: Record<string, IndicatorPageSnapshotRow>
  calculatedAt: string
}
```

每行包含：

```ts
type IndicatorPageSnapshotRow = {
  barKey: string
  sourceIndex: number
  time: number
  rsi?: RsiSnapshotRow
  macd?: MacdSnapshotRow
  stoch?: StochSnapshotRow
  vdo?: VdoSnapshotRow
  vmi?: VmiSnapshotRow
  // ...
}
```

快照只服务当前页面运行时，不是仓库文件。

## 8. runtimeOnly规则

已迁移的指标在 `ChartCoreHost` 中会传入：

```ts
runtimeOnly: true
```

含义：

- KLineChart `calc` 可以读当前页 snapshot。
- 如果 snapshot 命中，则按当前 `dataList` 的 `barKey` 映射结果。
- 如果 snapshot 缺失，则返回空行。
- 不允许在 KLineChart 生命周期里兜底重新计算。

这样可以避免：

- 缩放时重复计算。
- 拖动时重复计算。
- 参数变化时 KLineChart 内部隐式重算。
- 指标跨页读到历史旧数据。
- 当前页和其它页的结果混在一起。

## 9. 已接入规划器的指标

当前已按“页面规划器写快照，KLineChart 只读快照”接入的常规指标：

```text
MA
Stoch
VDO
VMI
TSI
AO
VI
RSI
MACD
DPO
```

这些指标的共同规则：

- 加载或参数变化时，由 `ChartCoreHost` 触发当前页计算。
- 计算结果写入页级 snapshot。
- KLineChart `calc` 只读 snapshot。
- draw 仍走 KLineChart 生命周期，保证坐标缩放和渲染同步。

特殊链路：

```text
VWAP
Vol
MMF_V3
MR-M5 / MR-M30
```

这些指标或结构仍有自己的特殊绘图/计算链路，但也必须遵守当前页、barKey、pageKey 的隔离规则。

## 10. VDO与VMI解耦

VDO 和 VMI 是两个独立指标，不应在运行状态上互相依赖。

当前设计：

```text
vdoCore.ts
  calculateVdoSourceRows(...)
  calculateVdoIndicatorRows(...)
  calculateVdoSmaSeries(...)

VDO
  使用 vdoCore 计算 VDO / VDO MA / VDO MA2
  写 vdoRows
  自己渲染

VMI
  使用 vdoCore 计算自己的 VDO source
  再按 VMI fast/slow 计算 histogram
  写 vmiRows
  自己渲染
```

原则：

- VMI 可以复用 VDO 的数学内核。
- VMI 不依赖 VDO 指标是否加载。
- VMI 不读取 VDO 指标的运行结果。
- VMI 的 `settingsHash` 不包含 VDO 指标状态。
- VDO 参数变化不隐式污染 VMI。

## 11. 计算触发条件

允许触发当前页指标重新计算：

```text
加载指标
卸载指标
修改指标参数
切换 symbol
切换 period
切换页面
实时页 K 线窗口变化
实时页新增 K 线
当前活动 K 线 OHLCV 更新
分页重置
```

不允许触发指标重新计算：

```text
缩放
拖动
十字光标移动
坐标轴缩放
普通重绘
tooltip 更新
对象树可见性变化
右侧抽屉切换 tab
```

这些行为只应触发 draw 或 overlay 更新。

## 12. 历史页规划

当前阶段历史页先保持不加载指标。

后续历史页接入时，也必须走同一套页面规划器：

```text
历史页 displayRows
+ warmupRows
+ lookaheadRows
-> calculationRows
-> 指标纯计算
-> 按 displayRows 的 barKey 回落
-> 写历史页 pageKey snapshot
-> KLineChart 只读 snapshot 渲染
```

关键点：

- warmup 数据不能显示到当前页。
- lookahead 数据不能污染当前页身份。
- 不能按数组下标简单切片对齐。
- 只按 `barKey` 把结果落回当前页。

## 13. 与右侧抽屉状态总线的关系

右侧抽屉状态总线记录的是“指标状态”，不是“指标计算结果”。

状态总线可以记录：

- 哪些指标已加载。
- 每个指标的 settings。
- 当前选中的指标。
- 指标设置面板 tab。
- pane 高度。
- 当前 runtimeKey。

状态总线不记录：

- 每根 K 线的指标值。
- 页级 snapshot 正文。
- StoreV6 仓库 K 线正文。
- 全量历史指标库。

指标计算结果属于页面运行时缓存，由页级 snapshot 管理。

## 15. 总体约束

后续新增指标必须遵守：

1. 指标包独立，不依赖其它指标运行状态。
2. 共享算法可以抽 core，但不能共享运行缓存。
3. 当前页计算由页面规划器触发。
4. 指标结果必须按 `barKey` 写入 snapshot。
5. KLineChart `calc` 只读当前页 snapshot。
6. `runtimeOnly` 下读不到 snapshot 就返回空行。
7. 不允许跨页取数据。
8. 不允许 zoom/drag 触发重新计算。
9. 实时页当前周期 OHLCV 必须保持周期一致。
10. StoreV6 不保存指标结果。

最终目标：

```text
StoreV6：干净 K 线和分页基础
页面规划器：当前页 K 线身份、指标计算、snapshot 写入
指标包：独立算法、绘图、tooltip
KLineChart：生命周期渲染，只读当前页缓存
状态总线：记录加载状态和参数，不记录指标结果正文
```
## 16. 指标预热规划器当前状态

`frontend/src/workbench/chart/indicatorWarmupPlanner.ts` 作为模块入口保留，但当前阶段不启用任何指标预热策略。

当前约定：
- 所有指标的 `warmupRows` 为 `0`。
- 所有指标的 `lookaheadRows` 为 `0`。
- 不记录“每个指标需要回补多少根”的规则。
- 不让 MMF_V3、MA、MR、VDO、VMI 等指标互相推导预热数量。
- 实时页不会因为空 warmup 额外写入 `pageCalculationContext`。

这样做的目的，是先稳定指标运行底座：

```text
当前页 displayRows
-> barKey 身份对齐
-> 指标纯计算
-> 当前页 snapshot
-> KLineChart 生命周期只读 snapshot 渲染
```

后续如果重新设计预热/回补，必须重新单独成章，不直接混入当前指标底座。
