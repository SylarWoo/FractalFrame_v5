# 回测系统暂行实施框架

## 定位

回测系统不是单独给某一个指标补功能，而是 MMF_V2 数据底座向策略验证、交易统计、K 线回放扩展的一套统一框架。

核心目标：

- 所有策略回测、交易结果表、K 线回放，都吃同一套 K 线、Feature Table、Signal Table。
- 后续接入 vectorBT 时，不重新造一套数据，而是把当前数据底座适配成 vectorBT 能直接消费的矩阵。
- 前端图表只负责展示和交互，不在前端重新推导策略结果。

暂行总链路：

```text
Store V5 / DuckDB / Parquet
        ↓
Market Data Table
        ↓
Feature Table
        ↓
Signal Table
        ↓
Strategy Decision Table
        ↓
Trade Table
        ↓
Backtest Report / Replay Timeline / Chart Jump
```

## 1. 统一输入数据

回测、图表、信号、策略都必须使用同一份标准 K 线表。

标准字段：

```text
symbol
timeframe
sourceIndex
barKey
time
open
high
low
close
volume
```

关键规则：

- `barKey` 是全系统主坐标，格式建议继续使用：`symbol|timeframe|time`。
- `sourceIndex` 是当前数据窗口内的行号，用于 vectorBT、前端数组和回放进度条。
- 跳转 K 线时优先用 `barKey`，不能只用浮动时间或裸 index。
- Store V5 是回测数据源，vectorBT 不直接访问 MT5。

## 2. Feature Table

Feature Table 是策略和回测的统一特征表，每根 K 线一行。

当前重点指标：

```text
MA
MR
Stoch
VDO
VMI
TSI
VWAP（预留）
```

示例字段：

```text
ma
maLength
maType
maSource

stochK
stochD

vdo
vdoBaseMa
vdoBase2Ma
vdoDelta
vdoDirection
vdoCrossUpBaseMa
vdoCrossDownBaseMa
vdoEnterOverbought
vdoExitOverbought
vdoEnterOversold
vdoExitOversold

vmiHistogram
vmiFastMa
vmiSlowMa
vmiDirection
vmiCrossUpZero
vmiCrossDownZero

tsi
tsiSignal
tsiHistogram
tsiCrossUpSignal
tsiCrossDownSignal

morgan_center
morgan_true_range
morgan levels
```

约束：

- 前端副图指标和后端策略指标必须逐步统一到同一套 Feature Table。
- 不允许一个策略模块自己重新算 VDO/TSI/VMI，然后和副图显示不一致。
- 所有参数由统一指标控制器进入，形成 `indicatorSettingsHash`。

## 3. Signal Table

Signal Table 是所有点位信号的统一输出表。

每个点位一行，不依赖前端图形状态。

标准字段：

```text
signalId
signalType
indicator
side
direction
role
barKey
sourceIndex
time
price
confirmed
confirmBarKey
confirmIndex
confirmTime
confirmPrice
source
reason
metrics
```

当前 MMF_V2 信号应该逐步统一进入 Signal Table：

```text
Stoch 高/低点
支撑位 / 阻力位
顶背离 / 底背离
多头市场 / 空头市场
超买开启 / 超买关闭
超卖开启 / 超卖关闭
TSI 金叉 / 死叉
TSI 金叉确认点 / 死叉确认点
上升趋势 - 回撤点
下降趋势 - 反弹点
```

规则：

- 信号模块只输出结构化数据，不直接决定前端怎么画。
- 前端 marker 是 Signal Table 的可视化结果。
- 策略和回测也消费同一张 Signal Table。
- 替换关系、叠加关系、优先级要在 signal catalog 中明确，不靠零散补丁。

## 4. Strategy Decision Table

Strategy Decision Table 是策略层，不是指标层。

它读取：

```text
Market Data Table
Feature Table
Signal Table
```

输出每根 K 线的策略决策：

```text
barKey
sourceIndex
time
positionState
entrySignal
exitSignal
entryAllowed
exitAllowed
targetPosition
orderSide
orderType
orderPrice
reason
```

说明：

- Signal Table 只说明市场发生了什么。
- Strategy Decision Table 才说明策略要不要买、要不要卖、要不要平仓。
- 同一个信号可以被不同策略解释成不同交易动作。

## 5. Trade Table

Trade Table 是用户最终查看的每笔交易结果表。

每笔交易一行：

```text
tradeId
strategyId
symbol
timeframe
direction

entryBarKey
entryIndex
entryTime
entryPrice
entrySignalType
entryReason

exitBarKey
exitIndex
exitTime
exitPrice
exitSignalType
exitReason

size
pnl
pnlPercent
barsHeld
maxFavorableExcursion
maxAdverseExcursion
fees
slippage
status
```

前端表格能力：

- 点击 `entryBarKey` 跳转到入场 K 线。
- 点击 `exitBarKey` 跳转到出场 K 线。
- 支持按策略、方向、盈亏、信号类型筛选。
- 支持把单笔交易在主图上高亮。

跳转规则：

```text
Trade Table entryBarKey
        ↓
Chart barKey resolver
        ↓
定位对应 K 线 index
        ↓
图表滚动到该 K 线并显示十字线/高亮
```

## 6. vectorBT 接入方向

vectorBT 作为批量回测适配层，不直接替代 MMF_V2 数据底座。

推荐位置：

```text
Feature Table + Signal Table + Strategy Decision Table
        ↓
vectorBT Adapter
        ↓
Portfolio / Orders / Trades / Stats
```

vectorBT Adapter 职责：

- 将 `close` 转成 vectorBT price series。
- 将策略入场条件转成 `entries` 布尔矩阵。
- 将策略出场条件转成 `exits` 布尔矩阵。
- 将方向转成 long/short entries/exits。
- 将手续费、滑点、仓位大小转成 vectorBT 参数。
- 将 vectorBT 输出的 trades 映射回 `barKey/sourceIndex`。

不建议：

- 不建议让 vectorBT 直接读取零散指标模块。
- 不建议让 vectorBT 自己重新计算 MMF_V2 信号。
- 不建议策略直接依赖前端 marker。

vectorBT 输出需要再标准化为 Trade Table，不能只保留 vectorBT 原始对象。

## 7. KLineCharts 回放系统

K 线回放可以直接基于当前 klinecharts 底座扩展，不需要更换图表库。

基本机制：

```text
fullRows: 全量 25000 根 K 线
currentIndex: 当前回放位置
visibleRows = fullRows.slice(0, currentIndex + 1)
chart.applyNewData(visibleRows)
```

回放控制器：

```text
ReplayController
  sourceRows
  currentIndex
  status: idle / playing / paused
  speed
  stepSize
  visibleRows
```

基础操作：

- 播放
- 暂停
- 单步前进
- 单步后退
- 快进 N 根
- 拖动进度条
- 跳转到某个 `barKey`
- 跳转到某笔交易入场/出场 K 线

关键约束：

- 回放模式下图表不能显示未来 K 线。
- 当前 index 之后的 marker、signal、trade 不能提前显示。
- 策略决策必须按 `currentIndex` 截断后的历史状态判断。

推荐实现：

```text
全量预计算 Feature Table
        ↓
Replay 时按 currentIndex 截断 Signal / Strategy / Trade 显示
        ↓
需要严格防未来函数的策略，再使用逐根状态机重放
```

## 8. 批量回测与实时回放的关系

批量回测：

- 适合 vectorBT。
- 一次性计算完整历史。
- 用于统计收益、胜率、回撤、参数扫描。

实时回放：

- 适合自建 Replay Engine。
- 一根一根推进。
- 用于观察策略是否在正确 K 线开仓、平仓。
- 用于人工复盘和调试策略逻辑。

二者必须共享：

```text
Market Data Table
Feature Table
Signal Table
Strategy Decision Table
Trade Table
barKey
```

## 10. 实施阶段

### 阶段 1：数据结构定型

- 定义 Market Data Table。
- 定义 Feature Table。
- 定义 Signal Table。
- 定义 Trade Table。
- 明确 `barKey/sourceIndex/time` 三套坐标关系。

### 阶段 2：MMF_V2 接入回测底座

- MMF_V2 输出标准 Signal Table。
- 当前前端 marker 改为从 Signal Table 派生。
- 保证主图点位、策略信号、回测信号完全一致。

### 阶段 3：Trade Table

- 先做最小策略样例。
- 输出 entry/exit/trade result。
- 前端表格支持点击跳转 K 线。

### 阶段 4：vectorBT Adapter

- 将 Strategy Decision Table 转成 entries/exits。
- 跑 vectorBT portfolio。
- 将 vectorBT trades 转回标准 Trade Table。

### 阶段 5：K 线回放

- 前端增加 ReplayController。
- 支持按 index 截断 K 线。
- 支持播放、暂停、步进、跳转。
- 交易表和回放联动。

### 阶段 6：策略调试面板

- 显示当前 K 线的 Feature Row。
- 显示当前 K 线的 Signal Row。
- 显示策略当前持仓状态。
- 显示本根 K 线为什么开仓/平仓/不操作。

## 11. 核心原则

1. 回测不是画图补丁，必须建立标准数据表。
2. vectorBT 是批量回测引擎，不是信号底座本身。
3. KLineCharts 负责回放展示，Replay Engine 负责时间推进。
4. 所有跳转必须基于 `barKey`。
5. 所有策略必须读统一 Feature Table 和 Signal Table。
6. 不允许策略、前端、副图各算各的指标。
7. 每个新增信号都必须先进入 Signal Table，再考虑图上怎么画。
