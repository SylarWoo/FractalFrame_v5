# 指标系统 V2 正规链路完善路线图

## 1. 当前结论

指标系统 V2 的主链路已经基本收口：

1. 右侧指标抽屉负责保存周期级指标状态。
2. `AppShell` 把已加载指标转换为 V2 指标请求。
3. 指标请求控制器负责历史页、实时页的预热和计算。
4. 历史窗口、实时窗口把 K 线和指标数据合并成统一窗口。
5. KLineChart render frame 把窗口数据翻译成渲染友好的 frame。
6. 指标生命周期模块把 frame 中的指标挂载到 KLineChart。
7. 副图 Y 轴、pane 高度、刷新恢复都进入统一生命周期。

这条链路完成后，指标不再依赖旧的命令式补丁挂载，也不再依赖某个周期的偶然缓存恢复。

## 2. 已接入的正规指标链路

### 2.1 主图指标

主图指标通过 V2 指标请求进入 frame，再由 KLineChart 主图 overlay 生命周期挂载。

- `MA`
- `MMF_V3`
- `MR-M5`
- `MR-M30`
- `MR-H2`
- `VWAP`
- `VOL`

其中 `VOL` 已改成 KLineChart 正规 indicator 生命周期，不再走外部 overlay canvas。

### 2.2 副图指标

副图指标统一走 V2 计算、snapshot、KLineChart 子窗格挂载。

- `RSI`
- `SQZMOM`
- `MACD`
- `DPO`
- `Stoch`
- `TSI`
- `AO`
- `VDO`
- `VMI`
- `VI`

这些指标现在都应该具备：

1. V2 指标定义。
2. 工作区指标注册。
3. `AppShell` 指标请求入口。
4. 历史页计算。
5. 实时页计算。
6. frame pane 合并。
7. KLineChart 子窗格挂载。
8. page snapshot 快照读取。
9. 副图 Y 轴交互。
10. 副图高度保存恢复。

## 3. 正规链路详解

### 3.1 指标状态入口

入口在右侧指标抽屉。

指标 Load/Unload 后，状态保存到周期级 UI 状态中：

```text
persistence/periodUiStateStorage
rightDrawer/indicatorPersistence
indicators/useIndicatorsController
```

周期隔离是必要条件。M5、M30、H2 的 loaded 状态、指标参数、抽屉选择状态不应该互相污染。

### 3.2 指标请求生成

`AppShell` 是指标总控台到 V2 计算链路的关键入口。

它把 `loadedIndicatorKeys` 转换成：

```text
StoreV6IndicatorRequestSpecV2[]
```

如果某个指标没有在这里加入 request，即使右侧抽屉显示 Load，后续预热、计算、frame、KLineChart 挂载也不会发生。

新增指标时必须检查：

```text
frontend/src/workbench/AppShell.tsx
```

### 3.3 指标定义注册

每个指标必须有 V2 definition，并注册到工作区 registry。

主要位置：

```text
frontend/src/workbench/chart/indicatorRequestV2
frontend/src/workbench/chart/chartWorkspaceIndicatorRegistryV2.ts
```

definition 负责说明：

- 指标 ID。
- pane ID。
- 主图/副图角色。
- 历史页计算方式。
- 实时页计算方式。
- warmup 行数。
- realtime update mode。

### 3.4 历史页计算

历史页走：

```text
useHistoryWindowIndicatorsV2
requestHistoryWindowIndicatorsV2
preheatHistoryWindowForIndicatorsV2
```

计算输入包含：

- 当前页 rows。
- warmup rows。
- display rows。
- 指标参数。
- 依赖指标结果。

输出写入：

```text
StoreV6HistoryPageWindow.indicators
StoreV6HistoryPageWindow.renderData.indicators
```

### 3.5 实时页计算

实时页走：

```text
useRealtimePageWindowForChartV2
requestRealtimeWindowIndicatorsV2
refreshRealtimeWindowIndicatorsV2
```

实时页分为：

1. 准历史稳定窗口。
2. 当前 active realtime rows。
3. 尾部 tick 更新。
4. 结算时刷新。

副图指标当前统一采用 `window` 模式，确保实时窗口有完整上下文，不只补最后一根。

### 3.6 frame 合并

历史窗口和实时窗口最终进入：

```text
buildCachedKLineChartRenderFrameV2
KLineChartRenderFrameV2
```

frame 是渲染系统唯一应该接收的数据结构。KLineChart 生命周期不应该直接回头访问右侧抽屉状态。

### 3.7 KLineChart 挂载

指标挂载统一由：

```text
klineChartIndicatorLifecycleV2
```

主图指标走主图 overlay 生命周期。

副图指标走子窗格生命周期：

```text
klineChartSubPane*V2
klineChartSubPaneIndicatorV2
```

副图指标挂载前会把 pane rows 写入：

```text
indicatorPageSnapshotStore
```

KLineChart indicator 的 `calc` 再通过 page snapshot 按 barKey 取数。

这保证了 KLineChart 生命周期内渲染的数据，和 V2 窗口计算出的数据保持一致。

## 4. M30 / H2 刷新恢复对齐

### 4.1 问题

之前 M30、H2 刷新后，副图指标高度容易恢复成默认高度，导致多个指标压在一起。

M5 看起来正常，主要是因为已有旧高度缓存或旧链路行为兜底，并不代表 V2 高度生命周期完整。

### 4.2 修正后的链路

副图高度恢复现在由 V2 统一处理：

```text
klineChartSubPaneHeightLifecycleV2
KLineChartHostV2
```

行为包括：

1. 创建 pane 时读取历史高度。
2. 拖动 KLineChart pane 分隔线时识别 resize。
3. resize 结束后保存所有可见副图高度。
4. `beforeunload` / `pagehide` 前保存一次。
5. 高度上限对齐旧链路，允许较大副图高度。

覆盖 pane：

- `rsi_pane`
- `stoch_pane`
- `sqzmom_pane`
- `macd_pane`
- `dpo_pane`
- `tsi_pane`
- `ao_pane`
- `vdo_pane`
- `vmi_pane`
- `vi_pane`

### 4.3 副图 Y 轴恢复

副图 Y 轴手动缩放恢复由：

```text
klineChartSubPaneAxisLifecycleV2
klineChartSubPaneAxisConfigV2
```

覆盖同一批副图 pane。新增副图指标必须同时进入高度配置和 Y 轴配置。

## 5. 维护规则

后续新增或改造指标时，必须按下面清单检查，不允许只补一个局部入口。

### 5.1 新增副图指标必做

1. 添加 V2 indicator definition。
2. 在 `indicatorRequestV2/index.ts` 导出。
3. 在 `chartWorkspaceIndicatorRegistryV2.ts` 注册。
4. 在 `AppShell.tsx` 把 loaded 状态转换成 V2 request。
5. 添加 KLineChart 子窗格安装器。
6. 接入 `klineChartIndicatorLifecycleV2`。
7. 写入 `indicatorPageSnapshotStore` 对应字段。
8. 加入 `klineChartSubPaneAxisConfigV2`。
9. 加入 `klineChartSubPaneHeightLifecycleV2`。
10. 增加测试覆盖。

### 5.2 新增主图指标必做

1. 添加 V2 indicator definition。
2. 注册到 workspace registry。
3. 接入 `AppShell` request。
4. 接入主图 overlay 生命周期。
5. 如果依赖其他指标，接入复合指标依赖编排。
6. 增加历史页和实时页测试。

### 5.3 禁止事项

1. 不要绕过 V2 request 直接在 UI 中调用 KLineChart 创建指标。
2. 不要让 KLineChart indicator 自己重新计算整页数据作为主路径。
3. 不要新增外部 overlay canvas 作为指标渲染主路径。
4. 不要只在 M5 验证恢复链路，M30 和 H2 必须一起验证。
5. 不要只处理历史页，不处理实时页。

## 6. 验证路线

### 6.1 逻辑测试

重点测试：

```text
indicatorRequestV2
klineChartSubPaneAxisConfigV2
klineChartSubPaneHeightLifecycleV2
```

需要确认：

1. 历史页只显示 page rows。
2. 实时页只显示 active rows。
3. 所有副图 pane 都进入 Y 轴生命周期配置。
4. 所有副图 pane 都进入高度生命周期配置。

### 6.2 浏览器验证

至少验证 M5、M30、H2 三个周期：

1. 打开多个副图指标。
2. 调整副图高度。
3. 刷新页面。
4. 确认高度恢复。
5. 拖动右侧 Y 轴刻度。
6. 确认不明显卡顿、不压缩到默认小高度。
7. 切换历史页和实时页。
8. 确认指标仍然挂载。

### 6.3 运行态检查

开发环境可检查：

```text
window.__ffIndicatorV2Perf
window.__ffKLineChartV2IndicatorLifecyclePerf
window.__ffKLineChartV2
```

关键判断：

1. Load 后 indicator perf 中有对应指标计算记录。
2. KLineChart 对应 pane 中能找到 indicator。
3. frame 更新时生命周期不是持续无意义重建。

## 7. 当前状态

当前 V2 指标系统已经完成以下收口：

1. 剩余副图指标已进入 V2 正规请求链路。
2. VOL 已进入 KLineChart 正规 indicator 生命周期。
3. 副图 Y 轴交互已覆盖全部 V2 副图指标。
4. 副图高度保存恢复已覆盖全部 V2 副图指标。
5. M5、M30、H2 应按同一套刷新恢复链路运行。

后续优化重点不再是“补挂载”，而是：

1. 单个指标 draw 性能优化。
2. 多副图同时加载时的重绘调度优化。
3. 历史页和实时页缓存命中率优化。
4. 更细粒度的浏览器自动化回归验证。
