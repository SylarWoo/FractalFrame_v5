# 工作区模板持久化底座架构说明

## 定位

工作区模板是 FractalFrame 的整体看盘状态导出/导入底座。

它不是单个指标的 Save/Unsave，也不是某一个右侧抽屉的局部保存，而是把当前浏览器端已经持久化的工作区状态打包成一个 JSON 文件。用户可以把这个文件当成看盘模板保存，再在当前端口或其它端口载入。

## 当前入口

前端入口：

- `frontend/src/workbench/settings/SettingsLayoutPanel.tsx`

底座模块：

- `frontend/src/workbench/persistence/workspaceTemplatePersistence.ts`

UI 入口放在：

```text
设置抽屉 -> 版面 tab -> 模板
```

当前有两个按钮：

- 保存模板
- 载入模板

## 保存范围

模板底座当前保存浏览器 `localStorage` 中所有以 `fractalframe:` 开头的 key。

这包括：

- 指标加载状态和指标参数
- 设置抽屉里的图表样式、状态行、坐标、事件配置
- 当前 MT5/数据中心相关局部状态
- 右侧抽屉宽度、当前激活抽屉
- 底部抽屉开关和高度
- 指标窗格高度
- 可见范围配置
- 图表视口缓存
- 画线、贴纸、对象树等已经接入 `fractalframe:` localStorage 前缀的状态

不保存：

- 后端数据库
- Store V5 的 parquet 数据
- MT5 实时连接状态
- 浏览器外部文件
- 没有进入 `localStorage` 的临时运行态

## 文件结构

导出的 JSON 结构：

```json
{
  "app": "FractalFrame_v5",
  "kind": "fractalframe.workspaceTemplate",
  "version": 1,
  "createdAt": "2026-05-31T00:00:00.000Z",
  "origin": "http://127.0.0.1:5185",
  "localStorage": {
    "fractalframe:v5:indicators:state:v1": "...",
    "fractalframe:settingsSymbolPanel:v1": "..."
  }
}
```

`localStorage` 里的 value 保持原始字符串，不在模板层二次解释。这样可以避免模板底座和各个业务模块互相耦合。

## 载入流程

载入模板时：

1. 用户选择 JSON 文件。
2. 前端检查 `kind` 和 `version`。
3. 只写回 `fractalframe:` 前缀的 key。
4. 写入完成后刷新页面。
5. 各模块按原来的读取逻辑重新初始化。

刷新页面是必要设计。因为图表实例、指标实例、抽屉状态、窗格高度等很多模块是在初始化阶段读取持久化状态，强行热更新容易造成半新半旧状态。

## 设计原则

模板底座只负责搬运状态，不理解状态。

各业务模块继续维护自己的 schema、默认值和归一化逻辑。模板载入后，如果某个字段过期或非法，仍然由对应模块的 normalize 函数处理。

这让模板系统可以先稳定工作，后续再逐步升级为更细粒度的 Profile 管理。

## 后续升级方向

后续可以在这个底座上继续加：

- 模板名称和备注
- 多模板本地列表
- 只导出指标/只导出画线/只导出版面
- 模板版本迁移器
- 自动备份最近 N 个工作区
- Python 后端模板目录
- 端口之间共享模板

当前版本先解决核心问题：把当前保存状态导出成文件，并能从文件恢复。
