# 页级指标快照底座升级计划

> 目标日期：2026-06-01  
> 适用范围：FractalFrame_v5 图表、MT5 StoreV5、MMF_V3、MR、VWAP、Stoch、VDO、VMI、TSI、MA 等指标。

## 1. 背景

当前 M5 实盘页在同时加载 MMF_V3、MR 和多个副图指标时会出现明显卡顿。根因不是单纯 K 线数量，而是图表渲染生命周期和指标计算生命周期混在一起：

- KLineCharts 在加载、拖动、缩放、实时 tick、指标参数变化时都可能触发指标 `calc`。
- 部分指标仍在前端计算或间接触发后台计算。
- 结果对齐曾经依赖数组下标，遇到 future placeholder、实时最后一根 K、换页异步返回时容易错位。
- M5 的数据密度、实时更新频率和 MMF_V3/MR 复杂度都高于 M30，因此 M30 不卡不代表 M5 底座稳定。

升级目标是把“计算”和“渲染”彻底分开：

```text
StoreV5/K线页 -> 页级指标快照计算 -> 指标快照缓存 -> KLineCharts 静态渲染
```

KLineCharts 不再负责指标计算，只负责显示 K 线、显示指标结果、响应拖动缩放和实时渲染。

## 2. 核心原则

### 2.1 K 线是唯一坐标源

每一根 K 线必须有稳定身份，不能只靠数组下标。

推荐统一字段：

```ts
type ChartBarIdentity = {
  symbol: string
  period: string
  time: number        // UTC seconds
  timestamp: number   // milliseconds for KLineCharts
  barKey: string      // `${symbol}:${period}:${time}`
  sourceIndex: number // 当前页真实 K 的顺序索引，不包含 future placeholder
}
```

所有后台指标结果必须至少返回：

```ts
{
  barKey: string
  time: number
  sourceIndex?: number
}
```

前端回填时优先按 `barKey` 对齐，其次按 `time` 对齐，最后才允许使用 `sourceIndex` 作为诊断辅助。禁止把后台结果直接按数组下标硬塞给图表。

### 2.2 页级快照是指标真源

当前页加载完成后，后台一次性计算这一页需要的指标，返回页级快照：

```ts
type IndicatorPageSnapshot = {
  pageKey: string
  symbol: string
  period: string
  pageIndex: number
  realtime: boolean
  barsCount: number
  settingsHash: string
  calculatedAt: string
  rows: IndicatorSnapshotRow[]
}

type IndicatorSnapshotRow = {
  barKey: string
  time: number
  sourceIndex: number
  mmfV3?: MmfV3Snapshot
  mr?: MorganRangeSnapshot
  ma?: MaSnapshot
  vwap?: VwapSnapshot
  stoch?: StochSnapshot
  vdo?: VdoSnapshot
  vmi?: VmiSnapshot
  tsi?: TsiSnapshot
}
```

KLineCharts 指标层只做映射：

```ts
return currentBars.map((bar) => snapshot.byBarKey[bar.barKey]?.mmfV3 ?? {})
```

### 2.3 实时页拆成两段

实时页不是整页每 tick 重算。

```text
第一页 5000 根：
  已收盘段：后台一次性完整计算，形成静态快照
  实时尾部：轻量更新，只处理当前未收盘 K 和少量尾部重算
```

建议默认策略：

- 前 4999 根已收盘 K：静态快照。
- 当前第 5000 根未收盘 K：前端更新 OHLCV，指标不每 tick 全量重算。
- 每 1-3 秒可选触发一次尾部轻量计算。
- M5 K 收盘时，后台重算尾部 200-500 根并合并到快照。
- 换页、换周期、改指标参数时，整页重新计算。

### 2.4 历史页完全静态

历史页没有实时 tick：

```text
打开历史页 -> 加载 5000 根 K -> 后台算整页指标 -> 前端静态渲染
```

历史页不需要尾部实时轻量计算。

## 3. 对齐协议

### 3.1 PageKey

页级快照必须有稳定 `pageKey`：

```ts
pageKey = [
  symbol,
  period,
  pageIndex,
  realtime ? 'rt' : 'hist',
  firstTime,
  lastTime,
  barsCount,
].join('|')
```

如果当前图表页的 `pageKey` 和快照 `pageKey` 不一致，前端必须丢弃快照。

### 3.2 SettingsHash

指标快照必须包含 `settingsHash`。它至少覆盖：

- 当前加载指标集合
- MMF_V3 参数
- MR 模式
- MA/VWAP/Stoch/VDO/VMI/TSI 参数
- 后台指标引擎版本

如果参数变化，旧快照不允许继续使用。

### 3.3 Future Placeholder

future placeholder 只属于前端显示层，不参与后台计算。

规则：

- 发给后台的 bars 不包含 future placeholder。
- 后台返回 rows 只覆盖真实 K。
- 前端合并到 KLineCharts 时，遇到 future placeholder 返回空指标 row。

### 3.4 异步返回保护

后台计算可能慢于用户操作。前端收到快照后必须检查：

- `pageKey` 是否仍等于当前页。
- `settingsHash` 是否仍等于当前设置。
- `symbol/period` 是否仍一致。
- `barsCount/firstTime/lastTime` 是否仍一致。

不一致则丢弃，不允许套到当前图表。

## 4. 后台计算模型

### 4.1 新增页级指标接口

建议新增统一接口：

```http
POST /api/indicators/page/jobs/start
GET  /api/indicators/page/jobs/result?jobId=...
POST /api/indicators/page/calculate
```

请求：

```ts
type IndicatorPageCalculateRequest = {
  pageKey: string
  symbol: string
  period: string
  pageIndex: number
  realtime: boolean
  bars: ChartBarIdentity[]
  indicators: string[]
  settings: Record<string, unknown>
}
```

响应：

```ts
type IndicatorPageCalculatePayload = {
  ok: boolean
  status: 'ready' | 'pending' | 'running' | 'failed'
  pageKey: string
  settingsHash: string
  snapshot?: IndicatorPageSnapshot
  error?: string
}
```

### 4.2 后台缓存

后台缓存 key：

```text
engineVersion + pageKey + settingsHash + barsChecksum
```

缓存内容：

- 完整 `IndicatorPageSnapshot`
- 计算耗时
- cacheHit / featureCacheHit
- 指标版本

### 4.3 计算顺序

后台内部可以共享 FeatureFrame：

```text
bars
  -> FeatureFrame
    -> MA
    -> VWAP
    -> Stoch
    -> VDO
    -> VMI
    -> TSI
    -> Morgan Range
    -> MMF_V3
  -> IndicatorPageSnapshot
```

MMF_V3 不再单独重复计算它依赖的基础特征，应尽量复用同一个 FeatureFrame。

## 5. 前端渲染模型

### 5.1 KLineCharts 职责

KLineCharts 只负责：

- 加载 K 线
- 滚动、缩放
- 实时更新 OHLCV
- 渲染指标快照
- 展示十字线 tooltip

KLineCharts 不负责：

- 计算 MMF_V3
- 计算 MR
- 计算 Stoch/VDO/VMI/TSI/VWAP/MA
- 触发后台计算

### 5.2 前端新增 Snapshot Store

建议新增：

```text
frontend/src/workbench/chart/indicatorPageSnapshotStore.ts
frontend/src/services/mt5/indicatorPageSnapshotApi.ts
```

Snapshot Store 负责：

- 保存当前页 `pageKey`
- 保存当前页 `settingsHash`
- 保存 `byBarKey` 索引
- 提供 `getRow(barKey)`
- 处理实时尾部 patch
- 处理旧请求丢弃

### 5.3 指标注册改造

每个 KLineCharts 指标的 `calc` 只读静态快照：

```ts
calc: (dataList, indicator) => {
  const snapshot = readCurrentIndicatorPageSnapshot()
  return dataList.map((bar) => {
    if (isFuturePlaceholder(bar)) return {}
    const barKey = assignBarKey(bar, snapshot.symbol, snapshot.period)
    return snapshot.byBarKey[barKey]?.mmfV3 ?? {}
  })
}
```

所有指标逐步从“计算型指标”迁移为“快照渲染型指标”。

## 6. 实时更新流程

### 6.1 实时页初始化

```text
1. 加载实时页 5000 根 K
2. 生成 pageKey
3. 请求后台页级指标快照
4. 快照 ready 后写入 Snapshot Store
5. 创建/刷新 KLineCharts 指标，指标只读快照
```

### 6.2 Tick 到来

```text
1. tick 更新当前 K 的 OHLCV
2. 前端更新 KLineCharts K 线
3. 不触发整页指标重算
4. 可选：节流请求尾部轻量计算
```

### 6.3 M5 收盘

```text
1. 当前 K 固化为已收盘 K
2. 新开一根实时 K
3. 后台重算尾部 200-500 根
4. 用 barKey 合并 patch 到当前快照
5. KLineCharts 刷新指标渲染
```

尾部 patch 格式：

```ts
type IndicatorSnapshotPatch = {
  pageKey: string
  settingsHash: string
  rows: IndicatorSnapshotRow[]
}
```

## 7. 历史分页流程

```text
1. 用户点击历史第 N 页
2. 加载该页 5000 根 K
3. 生成 pageKey
4. 后台计算整页指标快照
5. 前端写入 Snapshot Store
6. KLineCharts 静态渲染
```

历史页不做实时 tail patch。

## 8. 迁移阶段

### 阶段 1：对齐底座

- 新增统一 `barKey/time/sourceIndex` 生成工具。
- 图表加载页生成 `pageKey`。
- 所有后台指标请求带 `barKey`。
- 前端快照回填只按 `barKey/time` 对齐。
- 禁止新增基于裸 index 的指标对齐逻辑。

### 阶段 2：MMF_V3 页级快照

- 新增页级 MMF_V3 snapshot API 或先复用现有 MMF_V3 job API 封装成 page snapshot。
- MMF_V3 KLineCharts 指标改成只读 snapshot。
- 实时页只对尾部做 patch，不整页重算。
- 清理 MMF_V3 内部 `calc` 发请求逻辑。

### 阶段 3：MR 页级快照

- Morgan Range 后台计算并写入 snapshot。
- 前端 MR 覆盖物按 snapshot 渲染。
- 拖动窗口不触发 MR 计算。

### 阶段 4：基础副图指标迁移

迁移顺序建议：

1. MA
2. VWAP
3. Stoch
4. VDO
5. VMI
6. TSI

这些指标迁移后，KLineCharts 所有副图都只读 snapshot。

### 阶段 5：统一诊断

图表上增加轻量诊断信息：

- 当前 `pageKey`
- 当前 `settingsHash`
- snapshot 状态：loading/ready/stale/error
- 后台计算耗时
- cacheHit
- tailPatch 时间
- barsCount

## 9. 验收标准

### 功能验收

- M5 实时页加载 5000 根 K，MMF_V3/MR/副图指标全部能按 barKey 对齐。
- 切换历史页不会出现旧页指标套到新页。
- future placeholder 不参与后台计算，指标不漂移。
- 实时最后一根 K 更新不会导致整页指标重算。
- M5 收盘时尾部 patch 能正确合并。

### 性能验收

- 拖动图表时不发起指标计算请求。
- 缩放图表时不发起指标计算请求。
- 鼠标十字线移动不发起指标计算请求。
- tick 更新不触发整页指标计算。
- M5 全指标开启时，交互主要耗时应来自 canvas 渲染，而不是指标计算。

### 对齐验收

- 同一页同一参数，多次加载指标位置完全一致。
- 后台返回顺序变化不影响前端对齐。
- 删除/增加 future placeholder 不影响真实 K 指标位置。
- 历史页和实时页使用同一套 `barKey/time` 对齐规则。

## 10. 当前决策

1. M5 实时页默认 5000 根。
2. 历史分页默认 5000 根。
3. KLineCharts 不再作为指标计算引擎。
4. 后台是指标真源，前端只做快照读取和渲染。
5. 实时页采用“静态已收盘段 + 轻量实时尾部”。
6. 所有指标迁移前，必须先完成 `barKey/pageKey/settingsHash` 对齐协议。
