# 1. 数据中心主要模块

1. 搜索框，展示品种，详情，这一套，是从MT5，抓取，品种信息啥的。
2. 仓库，这个主要是，从MT5抓取历史数据，然后，聚合成各个周期。这也是一个主要模块。
3. 历史分页。

## 历史分页模块

1. 时间对齐分页器：根据周期在仓库数据中添加分页器。
   2. 日结触发模块。
   3. 自动更新模块。
2. 需求切片器：之后的某个模块需要某种数据，它会按照分页方法去找到对应数据。
3. K线数据请求器：它会向切片请求相应的数据，比如，当你点击第一页，它就请求出第一页，当你点击第二页，它就请求出第2页。
4. 指标总控台：
   1. 分为预热模块，主体数据模块。它要请求对应的K线数据，为了让这段数据指标全部覆盖，需要请求多一段的数据。
   2. MMF_v3 类指标需求模块：复合指标依赖编排模块
5. 历史窗口合并器：它会把K线数据，指标数据，合并到一个整体对齐的数组中。
6. 实时窗口合并器：
   1. 准历史数据模块
   2. 尾部更新模块
   3. 实时数据监视器
7. Klinechart 翻译器：它会把整齐的数组翻译成Klinechart 渲染友好的一段数据。
8. Klinechart 渲染前置数据合并器：
9. 分层缓存模块：
   1. 窗口数据缓存
      - 缓存历史页窗口、实时页窗口。
      - 比如第 1 页、第 2 页的原始窗口数据。
      - 指标以后也可以挂在这里。
  2. 翻译结果缓存
      - 缓存已经翻译成 KLineCharts 友好格式的数据。
      - 历史页不变，就不用重复翻译历史页。
      - 实时 tick 只改最后一根，就只更新实时段。
  3. 最终 frame 缓存
      - 缓存“历史段 + 实时段”合并后的最终 frame。
      - 切历史页时，只替换历史段。
      - 实时 tick 时，只替换/追加实时尾部。
      - KlineChart 只接收这个 frame。
10. 渲染系统推动器：
    1. 它会把最终此系统整理好的模块，直接推给渲染系统。
    2. 它应该是检查数据，有没有，完善不完善，然后，直接推送。
11. 缓存清理模块：
    1. 统一入口：`frontend/src/workbench/chart/historyPageCacheCleanupV2.ts`
    2. 历史页缓存清理：
       1. 触发行为：点击切换历史页、分页索引缓存失效、手动/自动重建分页。
       2. 清理范围：历史窗口缓存、渲染窗口缓存、最终 frame 缓存。
       3. 不清理实时窗口缓存；切换历史页时只替换历史段，再用新历史页重建 frame。
    3. 实时页缓存清理：
       1. 触发行为：每日停盘后自动触发。
       2. 清理范围：实时窗口缓存、实时 stable window 本地缓存、实时 page buffer、实时 page snapshot。
       3. 不清理历史窗口缓存；停盘后重新进入下一交易日实时窗口。
12. 刷新后自动推送器
13. 跳页移动模块
