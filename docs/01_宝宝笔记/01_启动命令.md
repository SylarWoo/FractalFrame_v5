# FractalFrame_v5 启动命令

> 当前 MMF 指标主线为 `MMF_V3`。MMF v1 / MMF_V2 只保留兼容，不再作为日常实盘入口。

## 1. 启动 MT5 本地后端桥

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts\mt5_symbols_server.py --host 127.0.0.1 --port 8765
```

这个窗口保持打开。它负责连接本机 MT5，并提供右侧数据中心需要的接口：

```text
Scan MT5 品种扫描
StoreV6 拉取
StoreV6 聚合
StoreV6 DuckDB 查询
MT5 tick/rates 实时参考
```

StoreV6 默认数据目录：

```text
runtime_data/store_v6
```

旧的 `runtime_data/store_v5` 只作为迁移期旧数据，不再作为新数据中心主链路。

### 一键启动

也可以在项目根目录执行：

```powershell
.\scripts\start_all.ps1 -OpenBrowser
```

这会启动后端桥，并同时启动三个前端工作区端口：

```text
http://127.0.0.1:5185/
http://127.0.0.1:5186/
http://127.0.0.1:5187/
```

5185、5186 和 5187 会读写各自的工作区配置档案，互不干扰。当前约定是 5185 作为 M5 工作区，5186 作为 M30 工作区，5187 作为 H2 工作区底座。

如果只想启动单个前端端口，可以执行：

```powershell
.\scripts\start_all.ps1 -FrontendPort 5185 -OpenBrowser
```

## 1.5 安装 MT5 交易时段导出脚本

StoreV6 需要本地交易时段规则文件。`Scan MT5` 会尝试读取 MT5/MQL5 导出的交易时段 JSON。

第一次使用前，建议安装导出脚本：

```powershell
.\scripts\install_mt5_session_exporter.ps1
```

然后打开 MT5 MetaEditor，编译并运行：

```text
Scripts\FractalFrameExportSymbolSessions.mq5
```

该脚本会导出：

```text
FractalFrame\mt5_symbol_sessions.json
```

后端扫描时会优先读取这个文件，生成 StoreV6 本地规则：

```text
runtime_data/store_v6/sessions/mt5_symbol_details.json
runtime_data/store_v6/sessions/trading_session_rules.json
runtime_data/store_v6/sessions/symbols/{symbol}.session_rule.json
```

如果没有导出文件，后端会尝试通过 Python MetaTrader5 session 函数读取；如果仍然读不到，后续可以用手工规则或历史 M1 反推规则补齐。

## 2. 启动前端页面

另开一个终端，在项目根目录执行：

```powershell
.\scripts\start_frontend.ps1 -OpenBrowser
```

这会先关闭本项目遗留的 Vite 前端进程，再用默认端口启动：

```txt
http://127.0.0.1:5185/
```

如果浏览器已经打开旧页面，启动后按 `Ctrl+F5` 强制刷新。

### 单独启动第二/第三工作区端口

如果不使用一键启动，也可以单独启动 `5186` 作为第二工作区端口：

```powershell
.\scripts\start_frontend.ps1 -Port 5186 -OpenBrowser
```

然后打开：

```txt
http://127.0.0.1:5186/
```

也可以单独启动 `5187` 作为 H2 工作区端口：

```powershell
.\scripts\start_frontend.ps1 -Port 5187 -OpenBrowser
```

然后打开：

```text
http://127.0.0.1:5187/
```

### 手动 Vite 命令

不需要脚本时，也可以手动进入前端目录：

```powershell
cd frontend
npm run dev -- --host 127.0.0.1 --port 5185
```

如果提示端口占用，先关掉旧的前端终端，或改用 `5186` / `5187`：

```powershell
npm run dev -- --host 127.0.0.1 --port 5186
npm run dev -- --host 127.0.0.1 --port 5187
```

使用前先确认 MT5 终端已经打开并登录。

## 3. 数据中心使用顺序

进入前端后，右侧 MT5 数据中心建议按这个顺序操作：

```text
1. 点击 Scan MT5。
2. 等待品种列表和详情扫描完成。
3. 确认 runtime_data/store_v6/sessions/ 下已经生成规则文件。
4. 选择交易品种，例如 XAUUSDm。
5. 点击 拉取。
6. 拉取完成后点击 聚合。
7. 图表和查询走 StoreV6 DuckDB。
```

`Scan MT5` 现在不只是刷新品种列表，还会同步 StoreV6 的前置规则缓存。后续拉取和聚合都会读取：

```text
runtime_data/store_v6/sessions/symbols/{symbol}.session_rule.json
```

拉取写入：

```text
Raw M1
Clean M1
barKey
sessionRuleId / sessionRuleVersion / sessionState / isTradingTime
```

聚合写入：

```text
M5 / M15 / M30 / H1 / H4 / D1 / W1 / MN
barKey
sourceFromOpenTime / sourceToOpenTime
sessionRuleId / sessionRuleVersion / sessionState / isTradingTime
```

K 线身份固定：

```text
barKey = symbol + "|" + period + "|" + openTime
```

交易时间、开市休市、缺口解释属于可重算扩展字段，不改变 `barKey`。

## 3.5 StoreV6 健康检查和修复

当前前端 bridge 已经切到 StoreV6，主要文件：

```text
frontend/src/services/mt5/storeV6Api.ts
frontend/src/services/mt5/storeV6JobsApi.ts
frontend/src/services/mt5/storeV6Types.ts
frontend/src/datafeed/storeV6KLineDatafeed.ts
frontend/src/workbench/mt5DataCenter/StoreV6Panel.tsx
```

前端请求应走 `/api/market-data/v1/store-v6/`，不要再把新数据中心接回 `/store-v5/`。

StoreV6 现在有独立 audit/repair 接口，用来核对 manifest 和 parquet 是否一致。

只检查：

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/api/market-data/v1/store-v6/audit?symbol=XAUUSDm" | ConvertTo-Json -Depth 8
```

检查并修复 manifest：

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/api/market-data/v1/store-v6/audit?symbol=XAUUSDm&repair=1" | ConvertTo-Json -Depth 8
```

它会核对：

```text
rowsCount
partsCount
firstOpenTime
lastOpenTime
firstTime / lastTime
聚合周期 lastTime 是否覆盖到 Clean M1 当前应有 bucket
```

如果发现聚合周期 manifest 显示已最新，但实际最后一根聚合 K 线落后，会把该周期标记为 `dirty=true`，下一次点击“聚合”会只重算尾部。

当前职责边界：

```text
拉取 = 只更新 Raw/Clean M1，不自动聚合。
聚合 = 只更新 M5/M15/M30/H1/H4/D1/W1/MN，普通模式走尾部增量。
校验 = audit/repair 修复 manifest 和 parquet 状态不一致。
```
